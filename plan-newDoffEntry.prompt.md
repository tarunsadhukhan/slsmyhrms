# Plan: New Doff Entry under Production

Add a second, simpler doff-entry screen ("New Doff Entry") under **Production** in the side drawer, placed right below "Spinning Doff Entry". It writes to the existing `daily_doff_tbl` (same as Spinning Doff) but with a numeric `mc_no` / `trolly_no` UX, live validation against `machine_mst` / `trolly_mst`, an auto-fetched running total/count per machine for the chosen date+spell, and a grouped summary list. Backend at `e:\sjm\attendancesystem` gets one new validation endpoint plus one summary endpoint; existing save/list endpoints are reused.

## Steps
1. **Drawer entries (UI):** Add a new `LinearLayout` `@+id/menuNewDoffEntry` directly below `@+id/menuSpinningDoffEntry` in [activity_dashboard.xml](app/src/main/res/layout/activity_dashboard.xml) (~line 1019), [activity_attendance_dashboard.xml](app/src/main/res/layout/activity_attendance_dashboard.xml) (~line 478), mirroring the existing markup with text "New Doff Entry".
2. **Drawer wiring:** In [ProductionDashboardActivity](app/src/main/java/com/example/slsHrms/ProductionDashboardActivity.kt) `setupMenus()`, [DashboardActivity](app/src/main/java/com/example/slsHrms/DashboardActivity.kt) (~line 630), and [AttendanceDashboardActivity](app/src/main/java/com/example/slsHrms/AttendanceDashboardActivity.kt) (~line 201) hook `menuNewDoffEntry` to launch `NewDoffEntryActivity` with `CO_ID` / `BRANCH_ID` extras (same pattern as Spinning Doff).
3. **New layout `activity_new_doff_entry.xml`:** Modeled on [activity_spinning_doff_entry.xml](app/src/main/res/layout/activity_spinning_doff_entry.xml). Rows: (1) Date picker + Spell spinner; (2) `etMcNo` numeric EditText with validation icon + `etTrollyNo` numeric EditText with validation lost focus (red/green border via `bg_input_invalid` / `bg_input_valid` drawables — add if absent); (3) `etGross`, `etTare`, `etNet` (read-only, auto-computed); (4) `etTotalDoffWt`, `etNoOfDoff` (both read-only, auto-fetched); (5) `btnSave` + `btnClear`. Below the card: a `RecyclerView rvDoffSummary` showing one row per machine: `mc_no | no_of_doff | total_wt`.
4. **New `NewDoffEntryActivity.kt`:**
   - On `etMcNo` focus-loss / text-change debounce → call new `validateDoffMachine(mcNo, branchId)` API; on success store `mcId`, set green border, then call `getDoffSummaryByMachine(date, spellId, mcId)` to populate `etTotalDoffWt` (sum of `net_weight`) and `etNoOfDoff` (count + 1 — i.e. next doff number).
   - On `etTrollyNo` blur → call `validateDoffTrolly(trollyNo, branchId)` returning `trollyId` + `trolly_weight` + `bucket_weight`; on success auto-fill `etTare = trollyWeight + bucketWeight`, set green border.
   - Net = Gross − Tare via `TextWatcher` (reuse pattern from Spinning Doff `recalcNet`).
   - `Save` → reuse `RetrofitClient.saveDoffTransaction(DoffSaveRequest(...))` with `qualityId = null`, `ebId = 0`. After success: keep date+spell, clear `mcNo`, `trollyNo`, weights, total, count; refresh summary list.
   - Summary list reload: call new `getDoffSummary(date, spellId, branchId)` → render with new `DoffSummaryAdapter`.
5. **API plumbing:** In [ApiRoutes.kt](app/src/main/java/com/example/slsHrms/api/ApiRoutes.kt) add `DOFF_VALIDATE_MACHINE = "doff/validate-machine"`, `DOFF_VALIDATE_TROLLY = "doff/validate-trolly"`, `DOFF_SUMMARY = "doff/summary"`. In [ApiService.kt](app/src/main/java/com/example/slsHrms/api/ApiService.kt) add three `@GET` calls. In [DoffResponse.kt](app/src/main/java/com/example/slsHrms/api/DoffResponse.kt) add `DoffMachineValidateResponse` (`status`, `mc_id`, `mc_name`, `mc_code`), `DoffTrollyValidateResponse` (`status`, `trolly_id`, `trolly_name`, `trolly_weight`, `bucket_weight`), `DoffSummaryRow` (`mc_id`, `mc_no`, `no_of_doff`, `total_wt`), and `DoffSummaryResponse`. Add new `DoffSummaryAdapter` next to [DoffTransactionAdapter](app/src/main/java/com/example/slsHrms/adapter/DoffTransactionAdapter.kt).
6. **Manifest + backend:** Register `NewDoffEntryActivity` in [AndroidManifest.xml](app/src/main/AndroidManifest.xml) next to `SpinningDoffActivity`. In backend `e:\sjm\attendancesystem` (mirror existing doff routes — likely `app.py` / a `doff_*.py` module): add `GET /doff/validate-machine?mc_no=&branch_id=` (lookup `machine_mst` by `mc_no` + branch), `GET /doff/validate-trolly?trolly_no=&branch_id=` (lookup `trolly_mst`), and `GET /doff/summary?date=&spell_id=&branch_id=` returning per-machine `COUNT(*)`, `SUM(net_weight)` from `daily_doff_tbl`. Save/list reuse existing `doff-transactions` endpoint that already targets `daily_doff_tbl`.

## Further Considerations
1. Should `mc_no` validation be triggered on blur only, on every keystroke (debounced ~400 ms), or only when user taps a "check" button? Recommend **debounced on text-change + on blur** for fastest UX.
2. "No of Doff" — should it represent the next doff number (count + 1, as you wrote) or the current count? I will implement **count + 1** per the request; confirm if you'd rather show plain count.
3. The new screen does not need Quality/EB (employee). Backend save accepts `quality_id = NULL` and `eb_id = 0` — confirm `daily_doff_tbl.eb_id` allows `0`/NULL, otherwise we'll pass the logged-in user's `eb_id`.
