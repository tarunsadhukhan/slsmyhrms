FIX #2: CHECKBOX SELECTION BUG
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

File: E:\sjm\MyHrms\app\src\main\java\com\example\myhrms\adapter\MachineSelectionAdapter.kt
Location: onBindViewHolder method (~line 32-56)

PROBLEM:
   Two click listeners both firing:
   1. holder.itemView.setOnClickListener { ... }
   2. holder.checkbox.setOnClickListener { ... }

   Flow:
   User taps row → itemView listener toggles checkbox to TRUE
                 → checkbox listener fires and toggles to FALSE
   Result: Checkbox blinks and returns to unchecked

OLD CODE (Broken):
   override fun onBindViewHolder(holder: ViewHolder, position: Int) {
       val machine = filteredMachines[position]

       holder.checkbox.isChecked = selectedMachineIds.contains(machine.id)

       // Problem: TWO listeners!
       val clickListener = View.OnClickListener {
           val newCheckedState = !holder.checkbox.isChecked
           holder.checkbox.isChecked = newCheckedState
           // Update Set...
       }

       holder.itemView.setOnClickListener(clickListener)  ← Listener 1
       holder.checkbox.setOnClickListener(clickListener)  ← Listener 2 (CONFLICT!)
   }

NEW CODE (Fixed):
   override fun onBindViewHolder(holder: ViewHolder, position: Int) {
       val machine = filteredMachines[position]

       // Set checkbox state from Set (single source of truth)
       holder.checkbox.isChecked = selectedMachineIds.contains(machine.id)

       // Make checkbox NOT directly clickable
       holder.checkbox.isClickable = false
       holder.checkbox.isFocusable = false

       // ONLY row click handler
       holder.itemView.setOnClickListener {
           val isCurrentlyChecked = selectedMachineIds.contains(machine.id)
           val newCheckedState = !isCurrentlyChecked

           if (newCheckedState) {
               selectedMachineIds.add(machine.id)
           } else {
               selectedMachineIds.remove(machine.id)
           }

           holder.checkbox.isChecked = newCheckedState
           onSelectionChanged(selectedMachineIds.size)
       }
   }

KEY CHANGES:
   ✅ checkbox.isClickable = false (no direct clicks)
   ✅ checkbox.isFocusable = false
   ✅ Only ONE listener: itemView.setOnClickListener
   ✅ State checked from Set, not checkbox itself
   ✅ Checkbox updated after Set is modified

RESULT:
   Click behavior now:
   1. User taps row
   2. ONLY itemView listener fires
   3. Set updated (add or remove ID)
   4. Checkbox visual updated
   5. No second listener to undo it!

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Bug #1: Database schema mismatch
   • Someone assumed column was "mach_code"
   • Actual database has "mech_code"
   • SQL query failed with column not found error

Bug #2: Event listener design flaw
   • Checkbox has built-in click behavior
   • Custom listener added to row AND checkbox
   • Both fired on same click → double toggle → looks like instant uncheck

Bug #3: Material Design default
   • Material TextInputEditText has no default textColor
   • Falls back to theme default (often black)
   • White dialog background + black text = hard to see
